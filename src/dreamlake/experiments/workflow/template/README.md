# PPO learning-rate sweep (HalfCheetah, toy)

**Question.** Does lr 3e-4 reach a higher eval return at the full 100k-step budget than 1e-4 and 1e-3?

- **Baseline:** lr 3e-4 (config `lr0.0003-…`).
- **Changed:** `train.lr` ∈ {1e-4, 3e-4, 1e-3}; 3 seeds each (`grids/lr.jsonl`, generated by `ppo_lr_generate.py`).
- **Fixed:** 100k steps, eval every 10k steps, log every 2k steps.
- **Primary metric:** `eval.return` (episode return, eval split) at the full budget; learning curves are partial evidence.
- **Evaluation:** every attempt whose training completes plays its final checkpoint without training noise
  (`play.py`); its named checks are recorded on that attempt. A failed check never fails the training run.
- **Analysis:** `analysis.py` judges this experiment's own criteria and publishes a report into `analysis/`.

## The four principal files

| File | Role |
|---|---|
| `ppo_lr_generate.py` | defines the combinations; writes the plan |
| `grids/lr.jsonl` | the committed plan (one row per config × seed) |
| `ppo_experiment_lr_launch.py` | runs plain `train.py` per row, records the attempt, then evaluates it with plain `play.py` |
| `analysis.py` | reads the server's contract and series, judges the criteria, writes and publishes the report |

`train.py` and `play.py` are ordinary code with no DreamLake import. The loop: generate → commit → launch
(train, then evaluate) → review in Dash → `python analysis.py` (exit 0: criteria met; 1: not met or
inconclusive; 2: the analysis itself failed).

## Conclusion

Draft. Synthetic example data: it only shows the workflow works, not a research result. When `analysis.py` has
published a report, its assessment is the one shown first in Dash; keep human context and limitations here.

## Limitations

Toy objective; 3 seeds; the criteria are reading aids, not significance tests.
